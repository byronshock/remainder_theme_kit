# Remainder theme kit

A palette chosen for what it is far from. Every color the kit authors clears
every semantically important pole of the realized color space — red, orange,
yellow, green, blue — so those keep meaning exactly one thing each and the
chrome means nothing at all. The authority is `AUTHORITY.md`.

A fork of the [De Stijl theme kit](https://github.com/byronshock/destijl_theme_kit),
which it owes everything structural and parts with on one question
(`AUTHORITY.md` §0b).

## The palette

| Role | Hex | L | C | Use |
|---|---|---|---|---|
| WHITE | `#EFE5E9` | 0.93 | 0.0120 | window backgrounds, fields, lists |
| LIGHT | `#B8AEB2` | 0.76 | 0.0127 | panels, buttons, non-key titlebars |
| DARK | `#4A4145` | 0.39 | 0.0139 | dock tiles, disabled text |
| BLACK | `#0F090C` | 0.15 | 0.0122 | rules, text, badges, the desktop field |
| ACCENT | `#773556` | 0.43 | 0.1007 | key titlebars, links, toggles, focus |
| SELECT | `#531537` | 0.31 | 0.0993 | selected rows, WHITE text on it |
| CURSOR | `#007891` | 0.53 | 0.0958 | text cursor, and the key window's frame — the one value at another hue |

Plus the three signal colors, unchanged from De Stijl and the only hues in the
system that mean anything: SUCCESS `#006B54`, WARNING `#FCD116`,
DESTRUCTIVE `#AF1E2D`.

## The one idea

Users arrive fluent in a color vocabulary nobody designed: red is an error,
green is done, blue is a link. A chrome painted in those colors makes a claim
whether or not its designer meant one, and no style guide reaches the user to
say otherwise. So the chrome vacates the vocabulary. What is left over after
every pole is removed is the remainder, and that is the kit.

The widest arc no signal claims runs 118.3° between blue and red. Its centre
is 323.2°; the kit authors at **351.0°**, shifted away from blue because a user
meets informational blue continuously and destructive red rarely. That shift
is a choice and is recorded as one — as is every chroma and lightness in the
kit. `build/derive_palette.py` labels each rather than dressing it as a
derivation.

Two metrics do two jobs, and they are not interchangeable: **APCA Lc** for
whether text is legible on a ground, **OKLab ΔE** for whether two grounds are
distinguishable. WCAG 2.x contrast is used nowhere — it rated four pairs
identically at "AAA 7.1:1" that APCA separates across Lc 52 to 79.

## Regenerate

```
python3 build/poles.py --bars              # the derived bars and the pole arcs
python3 build/derive_palette.py --write    # re-solve palette.json from poles.json
python3 build/remainder_space.py --check   # the icon ramp against §1 and §3
python3 build/qa.py                        # look at it (principle 12)
```

`palette.json` is generated. Change `poles.json` or the derivation and the
palette moves; editing the output is a defect, and so is editing a color in
`AUTHORITY.md` alone.

## Install

COSMIC (Pop!_OS), per-user, no sudo — it refuses to run under `sudo`, which
would theme root and leave your own desktop exactly as it is. Re-runnable, and
it saves what it replaces under `~/.local/state/remainder`.

```
sh worksafe/cosmic/install.sh
```

On a terminal that asks three questions before writing anything, and Ctrl-C
before the last one leaves the machine untouched:

1. **Fonts** — fetch and install Montserrat and Hack? Not asked when both are
   already on the machine. Default yes.
2. **Icons** — generate the icon theme from this machine's own icons? Not
   offered when the generator's dependencies are missing. Default yes.
3. **Background** — the museum photograph, the flat BLACK field, or leave the
   wallpaper alone. Default the photograph.

Every question also has a flag, and a flag answers its question in advance so
that question is not asked. With no terminal on stdin — a pipe, a provisioning
run — nothing is asked at all and the flags and defaults stand alone:

```
sh worksafe/cosmic/install.sh --all              # fonts and icons; background stays at the default
sh worksafe/cosmic/install.sh --fonts --no-icons # one of each
sh worksafe/cosmic/install.sh --icons-neutral    # icons on the neutral ladder alone
sh worksafe/cosmic/install.sh --black-field      # the §5 desktop: no photograph
sh worksafe/cosmic/install.sh --no-wallpaper     # keep whatever wallpaper is already set
sh worksafe/cosmic/install.sh --no-ask           # ask nothing, take the defaults
```

`--fonts` and `--icons` stay off unless asked for or answered for, and both are
the user's call (`AUTHORITY.md` §4, §5). `--fonts` fetches from the two projects themselves at a
pinned tag and refuses anything whose SHA-256 does not match. `--icons` repaints
nothing that is not already on the machine and is undone by selecting another
icon theme. Every pixel keeps its lightness exactly and takes its hue and chroma
from that lightness, along a ramp through the kit's own values — BLACK →
SELECT → ACCENT → LIGHT → WHITE, neutral at both ends and the home hue through
the middle, a duotone. So an icon keeps its shape, its shading, and its place
among the other icons; the dock comes back as itself in one register. That is
the intended result rather than a concession: the goal is not a colourless
interface but a colourful one that does not interfere with what you are doing,
since the hypothesis constrains hue against the signals (§0a) and says nothing
against colour as such (§0c). `--icons-neutral` runs the same machinery on the
neutral ladder for a user who wants the dock grey. The icon generator needs
Pillow, numpy and cairosvg — point `REMAINDER_PYTHON` at a venv that has them.

The repaint gives something up, and it is written down where it is made
(`build/remainder_space.py`): a pixel between two knots is an interpolation and
not one of the seven values §2 authors. The ramp passes through 667 distinct
8-bit values, five of them authored exactly. What replaces the stronger claim is
the one §1 actually sets — every value on the ramp clears every pole and none is
reserved (§3) — and `python3 build/remainder_space.py --check` proves it by
sweep rather than asserting it.

The default background is **Jar with Peonies and lid** (China, Ming
dynasty, 16th century; Fahua ware; Art Institute of Chicago 1938.454, Bequest of
Kate S. Buckingham), fetched from the museum at a pinned IIIF URL, verified
against a recorded SHA-256, and installed with its credit line beside it. It is
an open-access work whose two glazes land in the kit's unclaimed arcs and
nowhere else — aubergine `#532C48` in the home arc, below `C_FLOOR` and so
carrying no readable hue (ΔE 5.7 to SELECT), and teal `#00A3B7` in the cursor
gap, clear by 38.8° where 12.0° is required (ΔE 12.9 to CURSOR). Fahua ware
separates its glazes with raised slip trails so the colours cannot run
together, which is §5's geometry argument fired in a kiln.

Photographs are content (§0a, §5) and are permitted; nothing about this one is
authored and no value from it enters the palette. It has a measured cost and the
installer prints it: the object is shot on a light studio ground covering 71.1%
of the frame at L 0.74–0.80, so WHITE over it measures Lc −35.9 at the median
against −92.3 on the flat BLACK field. The surround stays BLACK — the image is
fitted, not zoomed, so the tiling gaps still read as the rule — but the middle of
the screen does not. It is the one place the kit knowingly ships under a floor
in §0e, which is why the question states the number before you answer it.
Answer 2, or pass `--black-field`, for the §5 desktop; `--no-wallpaper` keeps
your own.

Firefox, per-profile, no sudo, with Firefox closed. It asks one question — uBlock
Origin — and takes no for an answer by default:

```
sh worksafe/firefox/install.sh
sh worksafe/firefox/install.sh --ublock --no-ask     # answered in advance
```

The tab strip is the key titlebar, ACCENT with WHITE labels, and goes LIGHT with
BLACK ones when the window is not key — the one surface on this desktop that can
show it, since this libcosmic paints header bars with the window background.
Details, measurements and what is left over: `worksafe/firefox/README_FIREFOX.md`.

The all-sites sheet is the one thing in the kit whose reach is every site, which
is why it is in `elevated/` — not because it needs a password, since Firefox
hands an all-sites sheet to a per-profile extension and asks for nothing. Reach,
not privilege, decides the tier. It is loaded by Stylus, and importing it is a
manual step because Stylus imports through its own UI:

```
sh worksafe/firefox/install.sh --stylus   # sideload the extension
sh worksafe/firefox/install.sh --style    # print the file to import, and exit
```

**Import the JSON, not the CSS.** Stylus reads its own JSON export cleanly and
balks at a `*.user.css` file, so the kit ships both and they are not
interchangeable: `elevated/remainder.user.css` is the source a person edits, and
`elevated/remainder.stylus.json` is the file you import — Stylus › Manage ›
Import, and choose it. `--style` prints its path and exits.

§0a exempts content and a web page is content, so that sheet is a reader's choice
about their own screen and never the kit's: opt-in, off by default, and it stops
dead at images, video, canvas, SVG and anything a site coloured inline.

VS Code, per user, no sudo, and it may stay open — it watches its `settings.json`,
and the theme appears on the next window reload:

```
sh worksafe/vscode/install.sh                    # theme, type, and the declutter
sh worksafe/vscode/install.sh --no-declutter     # paint only
sh worksafe/vscode/install.sh --keep-file-icons  # leave workbench.iconTheme alone
```

It finds every VS Code under `$HOME` — Code, Code as a Flatpak, Insiders,
VSCodium — copies the theme extension into each one's extensions directory, and
merges two settings files into each `settings.json` after backing it up: the
theme, the type and the caret, and §0's declutter — the welcome page, tips,
recommendations, release notes, experiments, telemetry, the chat sidebar, motion.
The platform sets no font weight from a theme, so on this surface read text sits
on WHITE and LIGHT carries the icon strips and the headers the platform renders
bold; the status bar is the rule at the 22 px the platform fixes — half its 44 dp width. The editor cannot recolour
selected text outside a high-contrast theme, so its selection is LIGHT — measured,
and recorded as the platform's shortfall — while the terminal's is SELECT
carrying WHITE. Details, the ladders, the on-screen pass and what is left over:
`worksafe/vscode/README_VSCODE.md`.

Qt — every Qt 5 and Qt 6 application that reads its palette through qt5ct or
qt6ct, which on COSMIC is all of them (`start-cosmic` sets
`QT_QPA_PLATFORMTHEME=qt5ct`, and qt6ct answers to that name too) — per user,
no sudo, and applications may stay open, since both plugins watch their config:

```
sh worksafe/qt/install.sh                  # qt5ct, qt6ct, and the KDE colour scheme
sh worksafe/qt/install.sh --no-kde         # the two qt*ct targets only
sh worksafe/qt/install.sh --flatpak        # also point each Flatpak on the KDE runtime at kdeglobals
sh worksafe/qt/install.sh --platformtheme  # also set QT_QPA_PLATFORMTHEME for a desktop that does not
```

It copies a scheme into each tool's colours directory and merges six keys into
its config after backing it up: the scheme, the Fusion style, Montserrat and
Hack at 12 pt, and no motion. The same palette goes into `~/.config/kdeglobals`
as a KDE colour scheme, which Plasma reads and which a Flatpak on the KDE
runtime reads only with `--flatpak`. The Fusion style paints none of the
palette as given — every outline is the window darkened 40%, every button a
lightened gradient — so `build/qt.py` models the derivation in Qt's own
arithmetic and the on-screen pass found its bytes exactly; the one input
chosen against that model is `Button`, which is the COSMIC ladder's
`neutral_9` rather than LIGHT, because LIGHT's rendered face carries BLACK at
Lc 63 and `neutral_9`'s at 76. COSMIC exports a palette of its own into the
same files when "apply theme to other toolkits" is on, as Pop!_OS ships it;
its daemon keeps the kit's scheme path in `qt5ct.conf` and `qt6ct.conf` across
theme changes and rewrites `kdeglobals` at each one, and `README_QT.md` says
which is which and what to do about it.

Windows 11, administrator, and no terminal to fight — **double-click
`elevated/windows/install.cmd`** and it asks Windows for administrator itself. It
backs up every key it touches to `%LOCALAPPDATA%\Remainder\state\<date>-<time>\`
before it writes anything, and `install.cmd --restore DIR` puts a backup back.

```
install.cmd                    the colours, the accent, and the declutter
install.cmd --no-declutter     paint only; leave the recommendations in place
install.cmd --fonts            also substitute Montserrat for Segoe UI (HKLM, opt-in)
```

You can skip the script entirely: `remainder.theme` applies on a double-click and
both `.reg` files merge on one. The script exists for the three things a
double-click cannot do — back up what it replaces, order the steps so the theme
does not overwrite the accent, and restart the shell so you need not sign out.

It is in `elevated/` because it is the first surface in the kit that genuinely
needs a password. All of it but one file is `HKCU`; `fonts.reg` is `HKLM`, and a
residue elevation can remove is not residue (`CONTRIBUTING.md` §1) — Segoe UI in
the system chrome is exactly that case.

**What is measured there and what is not is stated rather than blurred.** The
colour work is gated by `build/windows.py`: every value, every pair's APCA Lc,
every adjacency's ΔE, and all five notations Windows stores colour in. The
*registry* claims — that a key exists on 24H2 and does what `PLATFORM.md` says —
are not measured, because this kit has no Windows machine;
`python3 build/windows.py --registry` prints them as a table to verify, never as a
gate. Details, the ramp, and the three steps no installer can do:
`elevated/windows/README_WINDOWS.md`.


## Status

The palette is settled and every floor is cleared. Six surfaces are built, each
with its own checker: COSMIC — the theme, the terminal scheme, the toolkit config
and an installer, checked by `build/cosmic.py`; Firefox — `userChrome.css`,
`userContent.css`, `user.js` and an installer, checked by `build/firefox.py`,
which measures every text pair and every adjacency the sheet authors rather than
taking a table on trust; and the all-sites sheet in `elevated/`, checked by
`build/stylus.py`, which also fails if any rule gives an authored colour to
content. The third surface added no new values: the kit's ten roles cover it. And Windows —
a `.theme`, two `.reg` files and a double-click installer in `elevated/windows/`,
checked by `build/windows.py`, which reads all five notations Windows stores colour
in and measures every pair the colours table states. The fourth added five, all of
them one ladder: the interior slots of Windows' eight-entry accent palette, where
indices 3 and 5 are ACCENT and SELECT exactly.

It is also the first surface the kit ships **without having run it**. There is no
Windows machine here, so its colour is measured and gated and its registry
plumbing is inherited from `PLATFORM.md` and marked unverified, key by key, by
`build/windows.py --registry`. That split is the deliverable as much as the theme
is. And VS Code — a theme extension, two settings files and an installer in
`worksafe/vscode/`, checked by `build/vscode.py`, which gates on the 299 ids
whose light default on 1.137 is a pole or a reserved literal (recorded, so the
gate runs anywhere) and re-reads the live registry off the installed build. The
fifth added four values, all of them content or signal: three diff tints and a
chart orange. And Qt — a palette for qt5ct and qt6ct and a KDE colour scheme in
`worksafe/qt/`, checked by `build/qt.py`, which emulates `QColor` to compute
the twenty-odd values Fusion derives from the palette and measures each, and
whose on-screen pass found those bytes exactly on Qt 5.15 and 6.4. The sixth
added no value: nine the kit already had, in two notations it had not yet
read. Not yet built: the Claude Code theme.
`AUTHORITY.md` §5 records what is inherited from De Stijl as convention rather
than measured, including the kit's weakest input: what "12pt" actually renders
at, which every contrast floor depends on.
